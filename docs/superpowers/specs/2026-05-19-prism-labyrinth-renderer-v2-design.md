## Direction & boundaries

- **Direction:** faithful port of the validated mockup. The mockup answered the design questions; this build executes against them.
- **Interaction model:** autoplay-first, scrubber-takes-over. Replay loops on page load; the first user touch (scrubber, dial, click) pauses autoplay and the scrubber position becomes the source of truth. A play button resumes from the current position.
- **Scope boundary:** Panel 1 only. Panels 2–4 are deferred per the build-prep spec; no class abstractions or shared scene infrastructure designed for them in v1.
- **Drift discipline:** this build does NOT include adjacent "AKIRA Core" / ARES-vision visual experiments (study HTMLs, pipeline diagrams, etc.). Those are separate cleanup work. The accumulated untracked files in the working tree at brainstorm time are explicitly out of scope.

**`prism.js` (scene + behavior, ~600 lines):**

| Section | Responsibility |
|---|---|
| **Constants** | `CHAMBERS` list (id, label, y, color), geometry constants (`CHAMBER_W=28`, `CHAMBER_H=4`, `CHAMBER_D=28`), `CYCLE_STAGGER_MS=240`, `CRUMB_STAGGER_MS=180`, drift color `0xef4444`, palette |
| **STATE** | `activeCycleIndex`, `autoplayRunning`, `operatorFilter`, `focusedPairIndex`, `pairs`, `visiblePairs` |
| **SCENE** | three.js refs (scene, camera, renderer, controls, pinGroup, chamberGroup) |
| **`initScene()`** | Scene + camera (fov 38, pos `[50, 0, 75]`) + renderer + lights + OrbitControls (autoRotate 0.25) + smooth-zoom override + resize handler |
| **`buildChambers()`** | Six BoxGeometry slabs at Y `[25, 15, 5, -5, -15, -25]`, wireframe edges (opacity 0.35), label sprites (left of each chamber, JetBrains Mono, chamber color), vertical connection lines (color `0x334155`, opacity 0.4) |
| **`loadTimeline()`** | `fetch('prism-timeline.json')`, validate top-level keys, store into `STATE.pairs` |
| **`renderCrumbs()`** | For each pair × each chamber: seeded-random position inside slab (`mulberry32(20260513)`); drift cycles go to corner `(x=11, z=11)` of the chamber matching `first_diverging_layer` |
| **`tickReplay(t)`** | Per-frame: opacity ramp (220ms in) for crumbs whose `activationMs ≤ t`, trail line updates, stat counters |
| **Controls** | `wireScrubber()`, `wireOperatorDial()`, `wirePlayPause()`, `wireCanvasClick()` |
| **`focusCycle(idx)` / `clearFocus()`** | Raycaster click-handler dims non-focused crumbs to opacity 0.06 |
| **`animate()`** | requestAnimationFrame loop: tickReplay → controls.update → render |
| **`init()`** | Bootstrap: loadTimeline → initScene → buildChambers → renderCrumbs → wireControls → animate |

The replay loop and the scrubber share `STATE.activeCycleIndex` — autoplay advances it via wall-clock time; scrubber interaction sets `autoplayRunning=false` and writes directly. One source of truth, two writers, never both active simultaneously.

## § 3 — Data flow

**Load:** `fetch('prism-timeline.json')` on page init → `STATE.pairs = data.pairs` (array of 98 pair records). Populate operator dial from `data.operators`.

**Pair → cycle trail mapping:** each pair becomes one rendered trail through the six chambers. The rendered cycle is the **mutated** trajectory (the adversarially-pressured one — that's where drift fires). `baseline_*` fields exist in the JSON but are unused by this renderer; reserved for Panels 2–4.

**Per-pair × per-chamber crumb placement:**

```
for pair P (pair_index = i):
  activationMs(P) = i * CYCLE_STAGGER_MS    // 240ms per pair

  for chamber C (index j, with C.y offset):
    crumbActivationMs = activationMs(P) + j * CRUMB_STAGGER_MS

    if P.broad_leakage AND C.id matches P.first_diverging_layer (case-insensitive):
      position = (x=11, y=C.y + small jitter, z=11)   // corner of slab, off-cluster
      color    = #ef4444                              // red drift
      radius   = 0.5                                  // bigger
    else:
      position = (seeded-random within (CHAMBER_W-4, CHAMBER_H-1, CHAMBER_D-4))
      color    = C.color                              // chamber hue
      radius   = 0.3
```

**Layer mapping (data → chamber):** `Architect` ↔ architect, `Skeptic` ↔ skeptic, `Oracle` ↔ oracle, `Final` ↔ verdict. `INPUT` and `FIREWALL` chambers never carry drift (deterministic in the pipeline); their crumbs are always chamber-color.

**Seeding:** `mulberry32(20260513)` — same seed as the mockup. Random sequence identical across loads; positions stable.

**Replay loop:** at wall-clock time `t`, `activeCycleIndex = floor(t / CYCLE_STAGGER_MS)`. Per frame, crumbs whose `crumbActivationMs ≤ t` are visible (with 220ms opacity ramp). Loop resets after `TOTAL_RUNTIME_MS` (≈ 24s + 5s pause).

**Operator dial:** filter pairs by `pair.operator === STATE.operatorFilter` (or `'all'`). Filtering re-computes the activation timeline against the filtered subset — visible count drops 98 → 33/32, replay duration shrinks proportionally.

**Click-to-focus:** raycaster hits a crumb mesh; reads `mesh.userData.pairIndex`. All crumbs with `pair_index ≠ focused` drop to opacity 0.06; focused trail stays at 1.0. Click empty space (or Esc) clears focus.

**Stats panel:** read off the same activation timeline. `cycles: N/98 · held: H · drifted: D` where `D = STATE.pairs.filter(p => p.broad_leakage && activationMs(p) ≤ t).length` and `H = N − D`.

## § 4 — Visual fidelity contract

**Faithful (no change from mockup):**

- Six chambers, Y offsets `[25, 15, 5, -5, -15, -25]`, colors per legend, `28×4×28` slab dimensions
- Wireframe edges (LineSegments on EdgesGeometry, opacity 0.35) + translucent fill (MeshStandardMaterial, opacity 0.04)
- Vertical connection lines between chambers (color `0x334155`, opacity 0.4)
- Label sprites to the left of each chamber (JetBrains Mono, chamber color, 384×64 canvas texture)
- Seeded-random crumb placement (`mulberry32(20260513)`)
- Drift signature: red `#ef4444`, off-cluster corner `(x=11, z=11)`, radius 0.5 vs held 0.3, emissive 1.6 vs 0.7
- Replay tempo: 240ms cycle stagger, 180ms crumb stagger, 220ms opacity ramp
- Auto-loop with ~5s pause at the end
- Stats overlay top-right with `mix-blend-mode: difference`
- Scene fog (`0x040408`, near 60, far 220), background `0x040408`
- Camera fov 38, initial position `[50, 0, 75]`, OrbitControls autoRotate 0.25
- Custom smooth-zoom override (step-based, lerped, ignoring `deltaY` magnitude)
- Page chrome: 50vw centered (92vw below 1100px), Inter body / JetBrains Mono labels, `#0a0a0a` background

**Changed (explicit, with reason):**

- **r160 ESM → r128 classic** — matches skyframe-main precedent
- **`DRIFTED_INDEX=1` hardcode → data-driven** — drift fires on pairs where `broad_leakage=true` at the chamber matching `first_diverging_layer`. Current dataset still resolves to a single pair at Oracle; survives future regens
- **`NUM_CYCLES=98` hardcode → `data.pairs.length`** — survives future dataset regen
- **Added: scrubber + operator dial + play/pause + click-to-focus** — per build-prep spec ("Full kit"). Mockup didn't have these
- **Added: `prefers-reduced-motion` gate** — when set: render all crumbs at final state immediately, disable autoplay loop and OrbitControls auto-rotate. Scrubber + dial still work. Mockup left this as a TODO

**Deliberately deferred (not in v1):**

- Baseline-vs-mutated dual trails (data supports it; defer)
- Confidence-as-glow encoding (mockup doesn't use it; defer)
- Hover tooltips with pair details (defer)

## § 6 — Error handling

**JSON load failure (network / 404):** wrap `fetch` in try/catch. On failure: replace `#loading` with `FAILED TO LOAD: <error.message>`, leave chamber wireframes visible, log to console. Matches the sphere-chain pattern (`prism-2026-05-14-sphere-chain.html:583-597`).

**Unexpected JSON shape:** validate top-level keys + first pair shape before rendering. Missing `pairs` or `operators` → show `FAILED TO PARSE TIMELINE` overlay. Belt-and-suspenders next to the Python contract test.

**Three.js / OrbitControls CDN failure:** check `typeof THREE === 'undefined'` inside `init()` before any scene code. On failure: replace canvas with text fallback (`3D RENDERER FAILED TO LOAD`). Matches `pinscreen.html`.

**WebGL not available:** check `renderer.getContext()` after `new THREE.WebGLRenderer(...)`. If null: same text fallback path. No Canvas2D fallback.

**Drift pair count ≠ 1:** the renderer iterates all `broad_leakage=true` pairs and renders each at the corner of its `first_diverging_layer` chamber. Stats panel reads `drifted: N`. No code path assumes exactly one drift; current dataset just happens to have one.

**Empty operator filter:** render empty pinGroup, stats `cycles: 0/0`, scrubber range `[0, 0]`. No error.

**`prefers-reduced-motion`:** render all crumbs at final state immediately, no autoplay, no auto-rotate. Scrubber + dial still work.
